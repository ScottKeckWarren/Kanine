# Data Model: Supervisor and Pup Workflow

**Date**: 2026-06-28
**Feature**: specs/001-supervisor-pup-workflow/spec.md

All state is in-memory within the supervisor process unless noted. Pups are stateless
between task assignments.

---

## Issue

Represents a GitHub issue as tracked within the supervisor. Extends GitHub's raw issue data
with supervisor-local state.

| Field         | Type                    | Notes                                               |
|---------------|-------------------------|-----------------------------------------------------|
| id            | int                     | GitHub issue number (unique within a repo)          |
| repo          | string                  | `owner/repo` slug                                   |
| title         | string                  | Issue title from GitHub                             |
| body          | string                  | Issue body markdown from GitHub                     |
| labels        | string[]                | All GitHub label names on the issue                 |
| column        | string                  | Derived: first matching column name from LabelMapper |
| pinned        | bool                    | Supervisor-local; excludes from autonomous dispatch |
| assignedPupId | ?string                 | UUID of the pup currently assigned; null if none    |
| fetchedAt     | DateTimeImmutable       | When the supervisor last loaded this issue          |

**Validation rules**:
- `id` and `repo` together form the unique key
- `column` defaults to first configured column if no label matches
- `pinned` is supervisor-local only; never written to GitHub

**State transitions**:
```
unassigned → assigned (Dispatcher assigns to a pup)
assigned   → unassigned (pup completes, fails, or times out)
any        ↔ pinned (operator action; pinned issues skip dispatch but remain visible)
```

## Pup

An agent process registered with the supervisor. Maps to the existing `Domain/Pup.php`.

| Field           | Type              | Notes                                              |
|-----------------|-------------------|----------------------------------------------------|
| id              | string            | UUID; set by the pup process at startup            |
| status          | PupStatus         | registered \| working \| blocked \| complete \| inactive |
| currentTaskId   | ?int              | GitHub issue number of active assignment; null if idle |
| lastHeartbeatAt | DateTimeImmutable | Updated on every poll request                      |
| registeredAt    | DateTimeImmutable | When the pup first called POST /pups/register      |

**Validation rules**:
- `id` must be a valid UUID v4
- `lastHeartbeatAt` must be within `pollIntervalSeconds × missedPollThreshold` of now
  or the pup is considered inactive

**Status transitions**:
```
(start)      → registered  (POST /pups/register)
registered   → working     (supervisor assigns an issue; pup reports working)
working      → blocked     (pup posts a question)
blocked      → working     (operator answers question; pup resumes)
working      → complete    (pup reports completion)
working      → registered  (pup reports failure; issue released)
any          → inactive    (missed heartbeat threshold exceeded)
inactive     → registered  (pup re-polls; supervisor reactivates)
```

## Task

The supervisor's view of an active or past assignment. Maps to existing `Domain/Task.php`.

| Field         | Type               | Notes                                         |
|---------------|--------------------|-----------------------------------------------|
| id            | int                | GitHub issue number                           |
| repo          | string             | `owner/repo` slug                             |
| state         | TaskState          | pending \| assigned \| working \| blocked \| complete \| failed |
| assignedPupId | ?string            | Pup UUID; null when pending                   |
| assignedAt    | ?DateTimeImmutable | Timestamp of assignment                       |
| completedAt   | ?DateTimeImmutable | Timestamp of completion or failure            |

**Validation rules**:
- `assignedPupId` MUST be non-null when state is assigned/working/blocked
- `assignedAt` MUST be set when state transitions out of pending
- `completedAt` MUST be set when state is complete or failed

## Question

A question posted by a pup to the supervisor when it needs operator input.

| Field       | Type               | Notes                                              |
|-------------|--------------------|----------------------------------------------------|
| id          | string             | UUID; generated by the pup                         |
| taskId      | int                | GitHub issue number the question relates to        |
| pupId       | string             | UUID of the pup that posted the question           |
| body        | string             | The question text                                  |
| postedAt    | DateTimeImmutable  | When the pup posted the question                   |
| answer      | ?string            | Operator's answer; null until answered             |
| answeredAt  | ?DateTimeImmutable | When the operator submitted the answer             |

**Validation rules**:
- `answer` and `answeredAt` are always set together
- Multiple questions can be open on the same task simultaneously
- Answered questions remain in the store for the pup to retrieve; cleared after retrieval

## Column

A named lane on the Kanban board. Driven by configuration.

| Field    | Type     | Notes                                                        |
|----------|----------|--------------------------------------------------------------|
| name     | string   | Display name shown as the column header                      |
| label    | string   | GitHub label value that maps an issue to this column         |
| position | int      | Left-to-right display order; 0-indexed                       |

**Validation rules**:
- Column names must be unique within a configuration
- Label values must be unique across all columns
- At least one column must be configured

**LabelMapper logic**: Given an issue's labels, return the column whose `label` value appears
first in the issue's label list. If no match, fall back to the column at position 0 (leftmost).

## Configuration Shape (reference)

```yaml
github:
  repositories:
    - owner/repo
  token_env: GITHUB_TOKEN

board:
  columns:
    - { name: "Backlog",     label: "status: backlog" }
    - { name: "Todo",        label: "status: todo" }
    - { name: "In Progress", label: "status: in progress" }
    - { name: "Review",      label: "status: review" }
    - { name: "Done",        label: "status: done" }

refresh:
  interval_seconds: 30

supervisor:
  host: 127.0.0.1
  port: 7777
  tls: false
  dispatch_interval_seconds: 2
  pup_timeout_seconds: 15
```

**Required keys**: `github.repositories`, `github.token_env`, `board.columns`,
`supervisor.host`, `supervisor.port`

**TLS enforcement**: If `supervisor.host` is not `127.0.0.1` or `::1`, `supervisor.tls`
MUST be `true` or config validation fails at boot.
